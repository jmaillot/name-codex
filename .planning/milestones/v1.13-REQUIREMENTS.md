## v1 Requirements — Completed

### Builder Drag & Drop

- [x] **BLD-01**: User can drag a segment via a drag handle to reorder builder segments with mouse, and the generated name and pattern preview update live — *Validated in Phase 30 (reorderSegments splice, GripVertical handle, insertion line, name/pattern recomputed on drop)*
- [x] **BLD-02**: User cannot drag fixed-first, fixed-last, or locked segments — pinned segments are non-draggable and show a visual blocked cue on attempted drag, while movable segments reorder correctly — *Validated in Phase 30 (draggable false, cursor not-allowed, isPinned guards, showFeedback)*
- [x] **BLD-03**: User can reorder segments via keyboard — Space/Enter to grab, ArrowUp/ArrowDown to move, Esc to cancel, Space/Enter to drop — with focus retained on the moved segment — *Validated in Phase 30 (handle tabIndex/role, kbGrabbedIndex snapshot, Arrow skip, Esc restore, focusHandle)*
- [x] **BLD-04**: User receives accessible feedback for reorder actions — dragged item has correct ARIA attributes (aria-grabbed/draggable, aria-label), and a live region announces grab, move, drop and cancel — *Validated in Phase 30 (aria-grabbed, sr-only aria-live polite, liveGrab/liveMove/liveDrop/liveCancel)*

### Builder Compatibility

- [x] **BLD-05**: User can still reorder segments via existing up/down buttons, and drag-and-drop coexists without regressions — remove and custom segment actions remain functional — *Validated in Phase 30 (moveSegment preserved, BuilderCard.test coexistence)*
- [x] **BLD-06**: User sees governance validation and score update correctly after drag reorder — no stale length, pattern or score state — *Validated in Phase 30 (validationResults/namingScore recomputed, check:data pass)*

## v2 Requirements — Deferred

### Builder Enhancements

- **BLD-07**: User's custom segment order is persisted per convention in localStorage and restored on next visit — *Deferred: state migration complexity for small gain*
- **BLD-08**: User can reorder segments via touch drag on mobile devices — *Deferred: native HTML5 sufficient for desktop*

### Presets

- **PRST-01**: User can save and reuse a builder configuration as a preset/template — *Deferred: out of scope for polish milestone*

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason | Outcome |
|---------|--------|---------|
| Persisting order per convention | Adds state migration and versioning complexity; deferred to v2 for small gain | Deferred as BLD-07 |
| Touch/mobile custom gesture handling | Native HTML5 drag sufficient for desktop; enhance later if mobile demand emerges | Deferred as BLD-08 |
| Builder redesign or preset system | Focus is reorder ergonomics only; full redesign is separate milestone | Deferred as PRST-01 |
| New conventions or segment libraries | Catalog mature at 71; no data additions this milestone | Upheld |
| Backend or collaboration features | App is static, local-only by design | Upheld |
