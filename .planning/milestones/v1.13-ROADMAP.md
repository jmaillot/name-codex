# Milestone v1.13: Builder Ergonomics — Drag & Drop

**Status:** ✅ SHIPPED 2026-09-03
**Phases:** 30-30
**Total Plans:** 2

## Overview

Make reordering builder segments fluid via drag handle and keyboard, respecting governance constraints, with live regeneration and no regressions. Delivered mouse drag (handle-only GripVertical, HTML5 DnD, insertion line) and keyboard (Space/Enter grab, Arrow skip pinned, Esc restore, focus retention) with ARIA live announcements and splice-based reorder guards.

## Phases

### Phase 30: Builder Drag & Drop Reorder

**Goal:** Enable mouse drag and keyboard reordering of builder segments with constraint awareness and accessible feedback
**Depends on:** Phase 29
**Plans:** 2 plans

Plans:

- [x] 30-01: Drag handle + HTML5 DnD reorder with constraint awareness and live preview
- [x] 30-02: Keyboard reorder + ARIA live region + button coexistence and validation regression coverage

**Details:**
- Drag handle is handle-only (`.builder-handle` draggable), `GripVertical` for movable, `Pin`/`Lock`/`Star` for pinned, cursor `grab`/`not-allowed`, dragging opacity 0.4 + dashed border, insertion line 2px accent skipping illegal slots
- `reorderSegments(from,to)` splice with `isFixedFirst`/`isFixedLast`/`isLocked` guards, barrier crossing checks, `showFeedback` toast, clamped index, validation/score recompute on drop only
- `BuilderCard` DnD container computes insertion index from mouse Y vs row midpoints, `preventDefault` only for legal positions, native ghost
- Keyboard: `tabIndex 0` + `role button` + `aria-grabbed`/`aria-pressed`, Space/Enter toggle grab, `ArrowUp/Down` single-step skipping pinned barriers, `Esc` restores snapshot via `restoreSegments`, focus retained via `segment-${sourceName}`, live region `aria-live="polite"` announces grab/move/drop/cancel/blocked
- Coexistence: up/down buttons, remove, addCustomSegment (fixedLast insertion) remain functional; `validationResults`/`namingScore`/`dynamicPattern` recomputed after reorder; regression tests in `BuilderCard.test.tsx` (9 tests)

## Milestone Summary

**Decimal Phases:** None

**Key Decisions:**
- Use native HTML5 drag over external DnD library (Rationale: linear list reorder sufficient, avoid dependency, proven through 71 conventions)
- Scope v1.13 to reorder ergonomics only — no persistence/new conventions (Rationale: catalog mature at 71, builder friction highest leverage polish)
- Handle-only draggable with GripVertical affordance (Rationale: clear affordance, pinned cues preserved)
- Direct splice reorder with clamped index and barrier checks mirrored from `moveSegment` (Rationale: never displace pinned, governance integrity)
- Token-compliant shadows via `var(--shadow-card)` (Rationale: pass `check:tokens` 18/18 WCAG)

**Issues Resolved:**
- Hardcoded `rgba` shadows violating `check:tokens` — replaced with `var(--shadow-card)`
- `BuilderCard.test.tsx` tsc errors (missing `generatedName`, unused vars) — fixed for `tsc -b`
- `reorderSegments` initial barrier logic over-restrictive — refined to crossing + neighbor checks per D-06

**Issues Deferred:**
- Persisting custom order per convention (BLD-07) — state migration complexity, deferred to v2
- Touch/mobile drag (BLD-08) — native HTML5 sufficient for desktop, enhance if demand emerges
- Builder redesign / preset system (PRST-01) — out of scope for polish milestone
