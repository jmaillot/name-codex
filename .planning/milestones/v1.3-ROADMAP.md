# Roadmap: v1.3 Developer Portal UI

**Status:** 🚧 IN PROGRESS
**Phases:** 8-10
**Milestone Goal:** Reskin and restructure Name Codex into an Azure Portal / Fluent-inspired developer-portal experience — dark navy layered surfaces, top command bar, collapsible left rail — with zero change to core naming/validation behavior.

## Overview

v1.3 Developer Portal UI transforms how Name Codex looks and feels without changing what it does. The work decomposes naturally into three delivery boundaries: first a semantic design-token foundation that repaints the existing layout in Fluent-style navy layers (theme applied, geometry untouched); then a layout restructure that moves navigation into a top command bar plus collapsible left rail; finally developer-portal polish — monospace styling for patterns/generated names/policy IDs, denser panel spacing — closing with a full zero-behavior-change verification pass. SAFE-01 is a **continuous constraint across all phases**: every phase ends with all 137 Vitest tests green, build + lint passing, PERF-01..03 intact, and EN/FR parity maintained.

## Phase Details

### Phase 8: Design Token Foundation

**Goal**: The app wears the Fluent-style dark theme — navy layered surfaces, off-white text, single accent — while keeping today's layout geometry untouched
**Depends on**: Phases 1–7 complete (v1.2 shipped — 137-test lock required as safety net)
**Requirements**: THEME-01
**Key Tasks:**

- Define semantic CSS custom-property tokens (`--surface-*` layer hierarchy, `--text-*`, `--accent`, borders/elevation) in plain CSS — no CSS framework
- Build navy surface hierarchy (no pure black) with off-white text and a single accent color
- Repaint existing components by consuming tokens only — no structural/layout changes to component JSX
- Verify contrast legibility of text on each navy layer

**Success Criteria** (what must be TRUE):

  1. Every colored surface/text/border/accent in the app resolves through semantic CSS custom-property tokens — swapping token values alone would produce a coherent alternate theme (future light mode = token swap)
  2. User sees a Fluent-style dark navy layered interface (no pure black backgrounds, off-white text, one accent color) while every screen, control and interaction sits exactly where it did in v1.2 — same geometry, same flows
  3. Text remains readable on every navy layer at typical sizes
  4. Zero behavior change holds: all 137 Vitest tests pass, build + lint green, PERF-01..03 optimizations intact, EN/FR parity unchanged

### Phase 9: Layout Restructure

**Goal**: Users navigate the app through an Azure Portal-style chrome — a top command bar with global controls and a collapsible left rail for convention categories
**Depends on**: Phase 8 (tokens must exist so new chrome consumes them, not hardcoded colors)
**Requirements**: LAYOUT-01, LAYOUT-02
**Key Tasks:**

- Build top command bar: app title/version, global search, language switcher, primary actions — relocating existing controls, no new behavior
- Build collapsible left rail navigation for convention categories, replacing the current nav placement
- Persist rail collapse state to localStorage following existing storage conventions (`name-codex-*`)
- Re-flow main content area around the new chrome, keeping all panels/features reachable and functional
- Update EN/FR locale files in parity for any new labels (rail toggle aria-labels, etc.)

**Success Criteria** (what must be TRUE):

  1. A persistent top command bar shows the app title/version, offers global search, language switcher (EN/FR), and primary actions — all previously available functions remain reachable from it or elsewhere
  2. All convention categories are navigable from a collapsible left rail; clicking a category selects it exactly as before
  3. Collapsing/expanding the rail works, and collapse state survives a full page reload / browser session restart
  4. Global search still finds conventions, and switching EN↔FR translates everything including the new chrome
  5. Zero behavior change holds: all 137 Vitest tests pass, build + lint green, PERF-01..03 intact, EN/FR parity unchanged
