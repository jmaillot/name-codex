# Requirements: Name Codex — Milestone v1.5 Naming Convention Expansion

**Goal:** Grow the convention catalog from 25 conventions across 7 categories to 45 across 11 categories — every new convention grounded in official Microsoft standards (CAF, learn.microsoft.com) and shipped as data-driven JSON with EN/FR parity.

## v1.5 Requirements

### Azure Expansion

- [x] **AZURE-01**: User can assemble a storage-account name following CAF (`st` + workload + environment + instance) with lowercase-alphanumeric-only / no-hyphen validation and the official 24-character global-uniqueness limit surfaced in validation
- [x] **AZURE-02**: User can assemble a key-vault name (`kv-workload-env-region`) honoring the official 3–24 char rule (start letter, end letter/number, no consecutive hyphens)
- [x] **AZURE-03**: User can assemble an NSG name per CAF (`nsg-<app/rule>-<instance>`)
- [x] **AZURE-04**: User can assemble a public-IP name per CAF (`pip-<app>-<env>-<region>-<instance>`)

### Microsoft Teams

- [x] **TEAMS-01**: User can build a project-team name with a `PRJ-` prefix and the ≤30-char visibility guidance enforced via maxLength
- [x] **TEAMS-02**: User can build a department-team name with a `DEPT-` prefix
- [x] **TEAMS-03**: User can build a service-team name with a `SRV-` prefix
- [x] **TEAMS-04**: User can build a name matching the Entra ID group naming-policy format `GRP_[GroupName]_[Department]` with attribute-token segments and blocked-words tip

### SharePoint / OneDrive

- [x] **SPO-01**: User can build a group-connected Team-site name (`/teams/<url>`), lowercase-hyphenated URL segment guidance
- [x] **SPO-02**: User can build a Communication-site name (`/sites/<url>`)
- [x] **SPO-03**: User can build a Hub-site name following Microsoft's consistent hub-naming recommendation (e.g. `<Function> Hub`)

### Power Platform

- [x] **PP-01**: User can build an environment name per ALM strategy (`<lifecycle>-<region>-<business unit>-<purpose>`), sandbox vs production type noted

### Purview / Compliance

- [x] **PURV-01**: User can build a sensitivity-label name from a classification taxonomy (Personal/Public/General/Confidential/Highly Confidential) with sublabel support
- [x] **PURV-02**: User can build a retention-label name (immutable-after-save warning in tips; no double quotes)
- [x] **PURV-03**: User can build a retention-policy name (7-day application lead time noted in tips)
- [x] **PURV-04**: User can build a DLP-policy name (old names persist in audit records — tip)

### Intune Expansion

- [x] **INTUNE-01**: User can build an Autopilot device-name template honoring the hard 15-char limit, allowed characters (letters/numbers/hyphens, not all numbers), and `%SERIAL%` / `%RAND:x%` macro segments
- [x] **INTUNE-02**: User can build an Autopilot Group Tag (department/site codes driving dynamic groups + per-group naming profiles)
- [x] **INTUNE-03**: User can build an update-ring name (Pilot/Dev/Broad/Production rings)
- [x] **INTUNE-04**: User can build assignment-group names using the `INTUNE-{DEV|USR}-<name>` taxonomy

### Quality & Integrity

- [x] **QUAL-01**: All 20 new conventions are data-driven JSON only (zero code changes), appear in category navigation with search, pass the existing JSON-integrity tests, hold EN/FR locale parity, and leave build/lint green

## Future Requirements

- SharePoint OneDrive library/folder naming convention (deferred — rarely standardized)
- Additional Azure resources beyond this batch (ACR, AKS, Cosmos DB, Service Bus… full CAF abbreviation list)
- Power Platform solutions/apps/flows conventions (publisher-prefix based) — deferred with environment only in scope
- DATA-01: JSON data layer validated by schema check and reference-integrity script before shipping
- DATA-02: Segment-level validation rules wired in (Region, Location, Environment, Instance, OS, PolicyId)
- LOCL-01: Additional languages beyond EN/FR

## Out of Scope

- Any backend, network layer, routing, or state library — app is static by design
- Schema-validation tooling for the JSON layer (DATA-01 stays future; existing vitest integrity tests suffice for this milestone)
- Enforcement integrations (e.g. generating Entra naming-policy PowerShell or Graph calls)
